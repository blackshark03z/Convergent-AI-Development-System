# DR-0007: Bound external specialist skills as pinned advisory inputs

Status: Accepted
Date: 2026-09-13
Scope: Skills / Knowledge / Supply Chain

## Context

CADS already assigns Knowledge-Gap Responsibility to the AI Tech Lead and uses targeted research when technical uncertainty is material. The remaining gap is narrower: when reusable external Agent Skill instructions are materially useful, CADS lacked an explicit rule for admitting exact reusable instruction bytes across sessions without letting those instructions acquire authority or create a package-management/runtime subsystem.

AutoSkills and the broader Agent Skills ecosystem provide useful prior art for stack detection, skill discovery, immutable source revision, content hashing, dry-run thinking and portable `SKILL.md` packaging. Those mechanisms do not establish CADS trust by themselves. Stack heuristics can false-positive; registry curation labels are not authority; hashes prove byte identity, not correctness; and skills may contain executable or live-fetching content.

## Decision

- Keep ordinary targeted research as the default response to knowledge gaps.
- Add one conditional External Specialist Skill Acquisition method only when a concrete reusable external skill is materially preferable to ordinary research.
- Treat every external skill as non-authoritative advisory engineering input. It cannot override Owner intent, CADS invariants, Goal/Acceptance, project/source/runtime truth, Decision Records or Consequence boundaries.
- Stack/framework detection is discovery evidence only; persistent use requires current-Goal relevance and active technology/version compatibility.
- Initial persistent support is docs/reference-only. Executable, opaque/binary or live network-fetching bundles are not persistently activated under this capability.
- Persist exact accepted content only when reuse is justified, with immutable source revision/path, bundle SHA-256, license and review provenance. Changed bytes require re-vetting; no background update occurs.
- Project-local acceptance does not make a skill CADS-recommended. CADS-wide recommendation requires representative outcome evidence and is scoped to the evaluated model/harness/version unless cross-harness evidence exists.
- Adopt Agent Skills / `SKILL.md` as a portability target for CADS-owned skills through deterministic generated projections. Existing CADS Markdown skill bodies remain the canonical semantic source.
- Do not adopt AutoSkills as a CADS dependency and do not create a CADS registry, marketplace, resolver, sync daemon, updater, trust service, skill database or second runtime.

## Consequences

- AI can reuse specialist knowledge without making the Owner repeatedly identify missing skills or re-explain engineering details.
- External instruction supply-chain identity becomes reproducible across sessions.
- v1 intentionally leaves executable external skill resources unsupported for persistent activation, reducing new attack surface.
- Agent Skills portability improves without manually duplicated vendor-specific CADS standards.
- Trigger descriptions are treated as behavior-bearing projection metadata and therefore tested alongside generated bytes.
- More skills are not presumed better; collision, stale-version advice, false triggering, context dilution and dependency creep remain reasons to reject/deactivate a skill.

## Revisit

Revisit executable/network-fetching external skills only if representative projects show material verified benefit that cannot be obtained safely from docs/reference-only skills. Revisit registry/signature infrastructure only if source-host identity becomes insufficient for demonstrated supply-chain needs. Revisit CADS-wide recommendations when matched eval/production evidence justifies promotion.
