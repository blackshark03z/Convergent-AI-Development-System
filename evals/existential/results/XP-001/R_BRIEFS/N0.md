**Outcome**

On the Production surface, keep the single current primary action visible and usable on supported desktop layouts without the Owner needing to scroll merely to find it. This must hold at the existing constrained desktop viewport of **1366×768**, while preserving the current Production workflow, task context, and action semantics.

**Acceptance**

- Add real-browser coverage for a populated Production state whose task content is tall enough to exercise the current layout problem.
- At **1366×768**, starting from the normal Production view at its initial/top scroll position:
  - do **not** call `scrollIntoView`, change `scrollY`, or otherwise pre-scroll before the assertion;
  - `#productionPrimaryAction` exists as the single current primary action;
  - its full bounding box is inside the visible viewport (`top >= 0` and `bottom <= innerHeight`);
  - it is visible/enabled as appropriate for that existing state and can be activated through the existing interaction path;
  - there is no horizontal page overflow.
- Preserve the same primary-action label, action mapping, handler, and resulting workflow behavior for the exercised state. The layout change must not create a second competing primary action.
- Preserve the existing semantic flow in which the current task/context is presented before its primary action; do not solve visibility by removing or bypassing that context.
- Do not introduce a nested vertical-scroll workaround inside the Production workbench.
- Existing normal-desktop behavior, including **1920×1080**, remains valid with no horizontal overflow.
- The browser regression must demonstrate the visibility condition **without scrolling the action into view first**.

**Constraints / Non-goals**

- Make the smallest coherent Production-layout change that satisfies the outcome.
- Do not redesign Production or unrelated Story Audio surfaces.
- Do not change Production state resolution, workflow ordering, action meanings, mutation boundaries, labels, or backend/provider behavior merely to solve layout visibility.
- Do not call external/paid providers or the canonical production runtime during verification; use isolated/local browser fixtures already supported by the repository.
